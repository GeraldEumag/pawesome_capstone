## Cat/dog compatibility trace

- **Selector:** `HotelForm.jsx` requests `/boarding/rooms/available` with selected species/date; customer booking modal does the same. Species-specific room labels/types are represented in `BoardingRoomService` and `ServiceCatalogManager`.
- **Server availability:** `BoardingRoomController` and `BoardingController::availableRooms` filter dog room types vs cat room types.
- **Server assignment:** `BoardingRoomService::createRoomReservation` checks `allowed_species`; `BoardingController` validates pet and room assignment and the reservation service is authoritative.
- **Roles:** customer and receptionist booking surfaces share the server availability/assignment rules rather than trusting a UI-only choice.
- **Evidence boundary:** unit/feature and E2E test files cover boarding/room workflow, but this audit did not run them because the test database and live stack were not verified isolated. Mark X-02 `PARTIALLY DONE`, not a fresh runtime PASS.

## Vaccination-card workflow trace (intentionally retained)

- Customer route: `POST /customer/boarding-requests/{id}/vaccination-card` (route group in `backend/routes/api.php`).
- Verification route: receptionist/admin verification endpoint `POST .../verify-vaccination`.
- UI: `HotelForm.jsx` requires and uploads the card; receptionist boarding manager reads/verifies it.
- Persistence: boarding card path and `vaccination_card_verified_at` schema migration.
- Scope: the user explicitly directed that this workflow remain. It is accepted and is not reported as missing or slated for removal.

## Receipt/payment trace and limits

- Upload → stored proof/receipt row → queued scan chain → normalized/validated extraction → cashier confirmation; no automatic payment acceptance is evidenced.
- `ReceiptBreakdown` is the backend source of `vat_inclusive`, net, VAT, total, payments, refunds, and balance. Receipt PDF and shared receipt component render those values; some labels do not explicitly say “VAT included.”
- Logo is loaded from the bundled `pawesome.jpg` by receipt/formal PDF utilities; the graceful no-logo fallback prevents a universal logo guarantee.
- `receipts:evaluate` is the documented accuracy evaluator. It was not run; do not claim extraction accuracy from static inspection or fake-provider tests.
