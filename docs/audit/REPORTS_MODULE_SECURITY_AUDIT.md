# Reports Module — Security Audit

**Date:** 2026-11-18

## 1. Role → report surface matrix (verified live on :8000/:8001)

| Role | `/admin/reports/*` | `/manager/reports/*` | `/cashier/*` | `/customer/reports/*` |
| --- | --- | --- | --- | --- |
| anonymous | 401 | 401 | 401 | 401 |
| customer | 403 | 403 | 403 | 200 (own records) |
| receptionist | 403 | 403 | 403 | — |
| cashier | 403 | 403 | 200 (own surface) | — |
| inventory | 403 | 403 | 403 | — |
| veterinary | 403 | 403 | 403 | — |
| vet_tech | 403 | 403 | 403 | — |
| manager | 403 (admin-only) | 200 | 403 | — |
| admin | 200 (all) | 200 | 200 | 403 by design |

All 88 report routes resolve inside `auth.api` + `throttle:api` + `role:` middleware —
enforcement is server-side (route groups), not controller-side trust of frontend claims.
Admin bypass is the documented all-access design; it is still denied the customer
portal surface (`role:customer` only).

## 2. Endpoint authorization review

| Area | Finding | Status |
| --- | --- | --- |
| Report reads | Every admin report route in `role:admin` group; manager payroll/attendance in manager group | PASS |
| Export endpoints | `customers/export` in same admin group as read route — no weaker binding | PASS |
| Alert mutation | `POST/DELETE /admin/reports/alerts` admin-only | PASS |
| Customer self-service | `customer/reports/*` queries scoped to `Auth::id()` (`customer_id`/`user_id`/`customer_email` match); no IDOR parameter accepted | PASS |
| Cashier verify/reject | `role:cashier` (admin bypass) + state-machine checks (only `pending` can verify/reject; approved-booking precondition) | PASS |
| POS transactions | `role:cashier` + `idempotency` middleware | PASS |
| Stock adjustments | `role:inventory`/admin + `idempotency`; add-type rejected (batch-only) | PASS |

## 3. Privacy & data exposure

| Check | Result |
| --- | --- |
| Customers see only own orders/pets/payments | Enforced by `where(customer_id|user_id|customer_email = auth)` — no override param | PASS |
| Clinical data | `medical_confinements`/`progress_notes` only via veterinary/admin/manager surfaces | PASS |
| Payroll/attendance | manager + admin only; `PayrollReports` page not exposed to other roles | PASS |

## 5. Export & injection safety

- `CustomerReportController@exportCustomerReports` streams CSV under admin role;
  formula-leading cells (`=`,`+`,`-`,`@`) prefixed with `'` — regression-tested
  (`test_customer_csv_export_neutralizes_formula_prefixes`).
- `UnifiedReportEngine` exports now use `filteredData` — export cannot smuggle
  rows outside the viewer's filtered/authorized result set.
- Payment proof / vaccination card uploads remain on `private` disk paths;
  report payloads return filenames/URLs generated by storage layer, not raw paths.
- No raw SQL string interpolation found in report code — all filters via query
  builder bindings (`LIKE` params bound).

## 6. Input validation hardening added this audit

- `validateReportParams()`: `YYYY-MM-DD` format + `from ≤ to` → 422 on all
  12 public admin report methods.
- `sales.limit` clamped to `[1,2000]`; cashier `per_page` ≤200, `page` ≥1.
- Malformed date → 422 (was silently ignored → wrong data); reversed range → 422.

## 7. Vulnerabilities found & dispositions

| ID | Severity | Issue | Disposition |
| --- | --- | --- | --- |
| SEC-1 | Medium | Invalid filters previously returned misleading 200 data (silent wrong answers) — an integrity issue more than disclosure | FIXED via 422 validation |
| SEC-2 | Medium | Uncapped `limit`/`per_page` → DoS-lean resource exhaustion on large exports | FIXED (clamped) |
| SEC-3 | Low | `payments()`/`cashier()` KPI counts computed on capped subsets could mislead approvers | FIXED (full-set counts) |
| SEC-4 | Low | `useReportData` 5-min cache could display stale figures as "live" | Resolved — dead hook deleted; live pages show `lastUpdated` |
| SEC-5 | Info | Dead code paths (`payrollReports`, `isAdminReport` branch) enlarge attack surface | Removed |
| SEC-6 | Watch | `APP_DEBUG` must be false in prod; dev-mode 500s leak file paths | Documented release-gate item, not a code defect |
